## 1. What the Current Approach Does

The H0 null distribution is generated inside `computeH0_BayesFactors()`
(`src/combination/copula.jl:514–659`) and underpins the copula mixture model
`π₀ · joint_H0 + π₁ · joint_H1`.

### Pipeline

```
Original InteractionData
        │
        ├──► permuteLabels()           # shuffle sample/control columns
        │    src/data/loading.jl:611   # within each experiment
        │    (bait row preserved)
        │
        ├──► Repeat div(n, n_proteins) times → vcat() → permuted dataset
        │
        ├──► betabernoulli()           # BF_detection  (fast)
        │
        ├──► main() per protein        # BF_enrichment + BF_correlation
        │    (same RxInfer HBM + regression pipeline as H1)
        │    priors τ0, μ0 from ORIGINAL data (NaN-safe)
        │
        └──► Filter zeros, remove bait → save copula_H0.xlsx
```

The resulting `H0` DataFrame (`bf_enrichment`, `bf_correlation`, `bf_detected`)
is converted to posterior probabilities and used to fit
`joint_H0 = SklarDist(copula_H0, (Beta₁, Beta₂, Beta₃))` in `combined_BF()`
(`copula.jl:879–893`).  The final combined Bayes factor for each protein is the
likelihood ratio `P(p | H1) / P(p | H0)`.

### Key design choices worth preserving

| Choice | Justification |
|---|---|
| Permute within-experiment only | Preserves batch/technical variance structure |
| Priors from original data | Prevents τ0 NaN on degenerate permuted variance |
| Bait row held fixed | Dose-response regression requires a valid reference signal |
| Same `main()` call for H0 and H1 | Systematic inference biases cancel in the ratio |
| Low-BF proteins added to H0 pool | Anchors null with real likely-non-interactors (`copula.jl:869–877`) |

### Bugs that were fixed (implementation, not methodology)

| Commit | Bug |
|---|---|
| `0579e7a` | Exponential dataset growth (`permuteLabels(permuted_data)` instead of `permuteLabels(data)`) |
| `7e3593c` | τ0 NaN when priors computed on permuted data |
| `7f3437e` | Total H0 computation failure on edge-case data |

## 2. Multi-Expert Critique

### 2.1 Biochemistry perspective

**Strengths**
Label permutation is biologically defensible for BF_enrichment and BF_correlation:
destroying sample/control assignment eliminates fold-change signal.

**Critical gaps**

- **CRAPome contaminants** (keratins, HSP90AB1, HSPA8, EEF1A1, ACTB, ribosomal
  proteins) are present in both sample and control with characteristic abundance
  profiles. Their BFs under permutation cluster near 1 — which is correct — but
  they have a fundamentally different null behaviour from rare candidate prey
  proteins, and pooling them into a single H0 inflates the tails.

- **Protein complex co-purification**: proteasome subunits, COP9 signalosome,
  nuclear pore complex constituents co-purify as a correlated cluster. The
  permutation preserves row-covariance, so these proteins all receive correlated
  null BFs. This underestimates the probability of seeing a random cluster of
  moderate BFs.

- **Proximity labeling bias (BioID/TurboID)**: spatial proximity to the bait,
  surface-lysine accessibility, and compartment membership drive systematic
  enrichment independent of direct interaction. Permutation destroys the
  sample/control assignment but does not model this compartment-level noise.

### 2.2 Bioinformatics perspective

**Limited permutation space**
With 3 samples and 3 controls per experiment, there are only C(6,3) = 20 unique
column permutations.  For a dataset with 1000 proteins,
`n_datasets = div(25_000, 1_000) = 25` permuted datasets are generated — most
of which repeat the same ≤ 240 joint configurations.  The 25,000-row H0
DataFrame contains massive pseudo-replication.

**Consequence**: the empirical marginal distributions of BF_enrichment,
BF_correlation, and BF_detection are artificially discretised; their tails are
underrepresented; and the copula fitting may converge to an over-concentrated
joint distribution.

**MNAR missingness**
LFQ data has Missing Not At Random (MNAR) patterns (low-abundance proteins below
the detection limit).  Permuting observed intensities does not generate the
correct missingness structure under H0.  TMT/iTRAQ data is far less affected due
to ratio compression.

**The augmentation heuristic** (appending proteins with BF_enrichment ≤ 3 and
BF_correlation ≤ 1.0 to the H0 pool) is statistically ad hoc.  It improves null
coverage in practice but could admit true low-effect interactors into the null.

### 2.3 Bayesian statistics perspective

**When permutation is valid**
Under the exchangeability assumption — sample and control labels are drawn from
the same distribution — label permutation is the correct pivotal null.  The
assumption holds exactly when there is no interaction.

**H0 misspecification consequences**
- Too-narrow H0 (under-dispersed): null proteins absorbed into H1 → inflated
  false positive rate.
- Too-broad H0 (over-dispersed): genuine interactors mistaken for null →
  reduced sensitivity.
Current pseudo-replication makes the H0 too narrow (discrete permutation space
oversampled), biasing toward the first failure mode.

**Identifiability of the EM mixture**
With the augmentation trick anchoring H0 with real low-BF proteins, the two
components are generally separable.  Risk is highest when the true interaction
fraction is > 20–25% (common in BioID experiments) or when genuine interactions
are weak.  The existing `prior = :empirical_bayes` path and BMA alternative
(`bma.jl`) already hedge against this.

**Theoretically cleanest null**
Under the Bayesian generative model, the exact null corresponds to simulating
data from the prior-predictive with μ = 0, β_slope = 0 (no enrichment, no
dose-response).  This is the construction used in Bayesian model comparison and
requires no exchangeability assumption.

### 2.4 Julia implementation perspective

**Dominant bottleneck**
Stage 1 (Beta-Bernoulli): negligible.
Stage 2 (HBM + regression via RxInfer `infer()`): ~99% of wall time.

```
~25,000 proteins × (1000 HBM iters + 150 regression iters) ≈ 28.75 M VB iterations
```

H0 computation dominates the first run of any analysis.

**Quick-win potential**
Reducing VB iterations for H0 from 1000 → 200–300 (HBM) and 150 → 50
(regression), and reducing n from 25,000 → 5,000–10,000, would yield a ~4–5×
speedup with negligible statistical impact.  The H0 needs an approximate, not
precise, null distribution.

### 2.5 Devil's advocate perspective

**Core challenge: where is the evidence of failure?**
No benchmarks, no documented false-positive analyses, and no comparison to
alternative H0 methods have been performed.  The three bugs fixed were
implementation errors, not methodology failures.  The system works.

**Dangers of each proposed alternative**
- Parametric null: a simple parametric form cannot capture the dependency
  structure of a complex hierarchical model. (A `H0_BF_enrichment()` LogNormal
  prototype existed but was removed without ever being wired into the main
  pipeline.)
- CRAPome: human AP-MS only; spectral-count format incompatible with intensity
  pipeline; experiment-specific backgrounds are not transferable.
- Empirical null from central mass: fails when signal fraction > 30%; requires
  tuning of the "null region."
- Prior-predictive null: same computational cost as permutation; priors may be
  misspecified enough to produce biased null.

**Minimum viable improvement**
Add a goodness-of-fit diagnostic to the existing pipeline: compare the fitted
Beta marginals and copula to the empirical H0 data using KS statistics.  Flag
when the fit is poor.  This is ~20 lines of code and zero risk of regression.

## 4. Recommended Strategy

### Tier 1 — Immediate (minimal risk, maximum ROI)

**A. Reduce H0 computation cost**
- `n` from 25,000 → 8,000 (sufficient for Beta/copula fitting; pseudo-replication
  already makes 25,000 largely redundant)
- HBM iterations: 1000 → 250 when called from `computeH0_BayesFactors`
- Regression iterations: 150 → 50 when called from `computeH0_BayesFactors`
- Skip the 6-threshold BF loop in `main()` when called in H0 mode (only
  threshold 0 is used: `result.bfHBM[1]`, `result.bfRegression[1]`)

Estimated speedup: **4–5×** with no measurable statistical impact.

**B. H0 fit diagnostic**
After fitting `joint_H0 = SklarDist(copula_H0, (H0_marg1, H0_marg2, H0_marg3))`
at `copula.jl:893`, run:
- KS test on each of the three Beta marginals against the empirical H0 data
- Multivariate energy statistic or Cramér's test on the joint
- Warn the user (and write to `em_diagnostics_file`) if any KS p < 0.05

This is the first objective measure of whether the H0 fit is adequate for a
given dataset.

### Tier 2 — Core improvement (medium complexity, clear benefit)

Two approaches are recommended here; they are complementary and both
significantly outperform pure permutation.  Choose based on priority:

#### Option 2A — Hybrid parametric-permutation null *(bioinformatician + biochemist)*

This addresses the pseudo-replication / small-permutation-space problem directly
while preserving all the structural advantages of the current approach.

**Algorithm:**

```
1. Run computeH0_BayesFactors with n_seed ≈ 2000–5000
   (enough to capture the copula dependency structure)

2. Fit parametric marginals to the seeded null:
   BF_enrichment  → LogNormal(μ_L, σ_L)   [or GeneralisedPareto for heavy tails]
   BF_correlation → LogNormal(μ_C, σ_C)
   BF_detected    → Beta(α_D, β_D)         [already done at copula.jl:890–892]

3. Fit the copula to the seeded null (unchanged from current code)

4. Generate n_final ≈ 50,000 H0 samples via:
   u ~ copula_H0           # preserves dependency structure
   bf_enrichment  = quantile(LogNormal(μ_L, σ_L), u₁)
   bf_correlation = quantile(LogNormal(μ_C, σ_C), u₂)
   bf_detected    = quantile(Beta(α_D, β_D), u₃)

5. Save to copula_H0.xlsx (same schema, fully backward compatible)
```

**Why LogNormal for enrichment and correlation BFs?**
Under no enrichment (H0), the log-BF for the HBM is approximately normal
(Laplace approximation of the Savage-Dickey ratio near the null point).
LogNormal for BF itself follows directly.  Empirical checks on permuted data
should confirm; GeneralisedPareto should be fitted instead if the tail is
heavier.

**Key properties preserved:**
- Copula structure fitted to real permuted data → dependency between evidence
  streams is data-driven
- Beta marginal for detection → already used downstream; no change
- Backward compatible: same H0.xlsx schema, same `combined_BF()` interface
- No external databases required

**Implementation scope:**
- `src/combination/copula.jl`: extend `computeH0_BayesFactors` with a
  `smooth_marginals::Bool = true` kwarg; add ~80 lines for marginal fitting +
  copula sampling
- No other files need to change

---

#### Option 2B — Prior-predictive null + Efron calibration *(Bayesian statistician)*

This is the theoretically cleanest option: it replaces the exchangeability
assumption entirely with the generative model itself.

**Algorithm:**

```
1. Draw τ ~ Gamma(a₀, b₀), set μ = 0, β_slope = 0  (true Bayesian H0)
2. Generate synthetic data matching the experimental structure
   (same n_protocols × n_experiments × n_replicates as original data)
3. Run the same main() function to compute all three BFs
   → joint BF dependency automatically captured
4. Repeat n_seed times (same cost as Option 2A)

5. Efron-style empirical calibration:
   - Transform both simulated and observed BFs to z-scores
   - Fit location (δ₀) and scale (σ₀) of simulated null z-scores
     to the central mass (~50%) of observed z-scores
   - This corrects for prior misspecification and experimental artifacts

6. Fit copula to calibrated null (same as current pipeline)
```

**Why this is theoretically superior:**
- E[BF | H0] = 1 by construction (exact Bayesian null, not an approximation)
- No exchangeability assumption — correct for batch effects and MNAR data
- Joint BF dependency captured automatically (same simulated protein drives all
  three BF computations)
- Efron calibration anchors the parametric null to the real data distribution,
  protecting against prior misspecification

**Practical caveat:**
The prior hyperparameters τ0, μ0 are themselves empirically estimated from data
(`τ0(data)`, `μ0(data)`) that contains both null and signal proteins.  This
creates a mild circularity.  The Efron calibration step mitigates this.

**Implementation scope:**
- `src/combination/copula.jl`: replace the `permuteLabels()` call (lines
  523–528) with a prior-predictive data generator; add ~30 lines of Efron
  calibration code; keep everything downstream identical
- Adds a `h0_method::Symbol = :permutation` kwarg (`:prior_predictive` for
  this path)

> **Note:** Efron's empirical null as a standalone method (without the
> prior-predictive simulation) requires the observed BFs to already be computed,
> meaning `analyse()` would need restructuring — H0 is currently loaded/computed
> *before* the main BF loop (`pipeline.jl:137–148`).  The hybrid approaches
> above avoid this circular dependency.

---

**Choosing between 2A and 2B:**

| Criterion | Option 2A (hybrid permutation) | Option 2B (prior-predictive) |
|---|---|---|
| Theoretical purity | ✓✓✓ (good) | ✓✓✓✓ (exact Bayesian) |
| Implementation change | Minimal (extend existing loop) | Moderate (replace data gen) |
| Captures experimental artifacts | Yes (via permuted seed) | Partially (via calibration) |
| Handles batch effects | Yes | Yes (no exchangeability) |
| Risk of prior misspecification | Low | Low (calibration corrects) |
| Recommended first | ✓ | ✓ (if theoretical rigor is priority) |

### Tier 3 — Optional enhancements (when data is available)

**A. CRAPome-informed contaminant stratification**

When analysing human AP-MS data, the existing curation pipeline
(`src/data/curation.jl` + `src/data/string_api.jl`) can be extended to query
CRAPome frequencies.  Proteins with CRAPome frequency > 50% receive a fixed
BF = 1.0 in the null (correct by definition) and are excluded from the
parametric marginal fits, preventing contaminant abundance patterns from
inflating the tails.  Proteins with frequency 10–50% can be
down-weighted.

This is architecturally consistent with the existing curation pipeline and
requires no new Julia dependencies.  CRAPome is human/mouse only; the feature
should be gated behind `use_crapome::Bool = false` in `CONFIG`.

**B. Cross-bait empirical null**

When a user provides `negative_control_data::Vector{InteractionData}` (AP-MS
experiments with unrelated baits run in the same lab under the same conditions),
compute BF triplets for all proteins in those experiments and use the result as
the H0 pool directly.  This is the most biologically realistic null possible and
subsumes both permutation and CRAPome approaches.

Implement as an optional path in `computeH0_BayesFactors`:
`if !isnothing(negative_control_data) ... end`.

References: SAINTexpress (Teo et al. 2014), CompPASS (Sowa et al. 2009),
MIST (Jager et al. 2011).

**C. Prior-predictive null calibration**

As a calibration check (not as a replacement), simulate null BF triplets from
the model's prior with μ = 0, β_slope = 0, and compare their marginal and joint
distributions to the permutation-derived H0.  Large disagreement signals prior
misspecification.  This requires no additional data and uses the existing
`main()` infrastructure; it is primarily a diagnostic tool.

## 7. What Not to Do

Following the devil's advocate analysis, the following directions are explicitly
**not recommended**:

- **Replacing permutation entirely with a standalone parametric model** — a
  single marginal parametric form (LogNormal-style calibrated tail) cannot
  capture the joint copula dependency structure of the HBM + regression +
  Beta-Bernoulli outputs.  A prototype `H0_BF_enrichment()` LogNormal builder
  existed in earlier copula.jl and was removed without ever being activated.
  The hybrid approaches in Tier 2 retain the copula structure from permuted
  data precisely to avoid this gap.

- **Using CRAPome as the primary H0 source** — format incompatibility (spectral
  counts vs. intensity), species restriction (human/mouse only), and
  experiment-specific backgrounds make it unsuitable as a standalone null.

- **Bootstrap within-condition as primary null** — creates correlated null
  samples; theoretical justification for breaking sample/control signal via
  independent within-group resampling is weaker than permutation exchangeability.

- **Any change before adding the diagnostic** — the diagnostic should be the
  first change merged, because it is the only way to objectively measure whether
  any subsequent improvement actually helps.
