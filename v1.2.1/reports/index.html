Reports

Overview

BayesInteractomics packages every analysis run into a single, self-contained interactive HTML report that combines results tables, diagnostic plots, calibration curves, structural-evidence summaries, and the publication-ready methods text. Reports are designed to be opened in any modern browser, shared as a single attachment, and navigated by biologists and methods reviewers alike.

Two report types are produced:

  1. Standard analysis report — generated automatically at the end of run_analysis. Tabs adapt to the analyses you actually ran.
  2. Differential analysis report — generated by differential_analysis when comparing two conditions.

The header shows the package version pulled directly from Project.toml via pkgversion(@__MODULE__), so the version banner is always in sync with the installed package — there is no manual version string to keep up to date.

Standard report file size is ~225 KB for a typical 5000-protein analysis (a ~98% reduction since v1.1.2: PNG static plots were replaced by Plotly.js JSON traces, and the data blob is compacted before being embedded).

The report API lives in the BayesInteractomics.Reports organisational submodule; its public symbols (generate_report, generate_differential_report) are re-exported at the top-level BayesInteractomics namespace, so they are available unqualified after using BayesInteractomics.

Quick Start

using BayesInteractomics

config = CONFIG(
    # ... analysis parameters ...
    generate_report_html = true,         # default: true
    output = OutputFiles("/path/to/results")
)

final_df, analysis_result = run_analysis(config)
# Report saved to config.output.report_file
# Default: <basedir>/interactive_report.html
# Methods text: <basedir>/methods.md
# Sidecar JSON:  <basedir>/interactive_report_data.json

To regenerate the report manually after the analysis (for example, after a docking pass):

generate_report(final_df, config)
generate_report(final_df, config; output = "/tmp/custom_report.html")

The generate_report_html::Bool field on CONFIG controls auto-generation at the end of run_analysis; set it to false to skip the HTML build (the methods markdown file is still written).

Tab Inventory

The report renders a fixed dashboard row at the top (top-line counts: number of proteins evaluated, number significant at BFDR ≤ 0.05, number of strong interactors at BFDR ≤ 0.01) followed by tabs whose visibility depends on which analyses were actually run. The two always-visible tabs are Results and Methods; everything else is shown only when the underlying analysis output is present in the report's JSON blob.

The current tab list (in display order) is:

Results tab

The Results tab is the entry point and always opens first. It contains:

  • Volcano plot — Plotly.js scatter with x = log₂FC and y = log₁₀(combined Bayes factor). Points are coloured by Posterior Error Probability (PEP) using the four-band scheme: grey for PEP > 0.05, amber for PEP ≤ 0.05, dark blue for PEP ≤ 0.01, and red for PEP ≤ 0.001. Three reference lines mark the BFDR ≤ 0.05, ≤ 0.01, and ≤ 0.001 thresholds. Hover reveals protein name, posterior probability, BFDR, PEP, individual Bayes factors, and log₂FC. Clicking a point selects that protein everywhere (see Cross-tab synchronisation below).
  • Rank-rank plot — log₁₀(combined BF) on the x-axis, log₂FC on the y-axis, and log₁₀(BF correlation) encoded as colour. Helps identify proteins that rank consistently as strong interactors across multiple evidence streams.
  • Results table — Sortable, filterable DataTables.js table. Columns include Protein, posterior_prob, BFDR, PEP (= 1 − posteriorprob), `localfdr, the combinedbf, thebfemandbfcopulasub-model Bayes factors (toggleable via the "Show sub-model BFs" checkbox), the individualbfenrichment/bfcorrelation/bfdetection,log2FC, and the classification label. When sensitivity analysis is enabled, additional columns showdiagnosticflag(:ok/:warning/:fail) andsensitivityrange(posterior variation across prior settings). When docking is enabled, columnsposteriorprobms,bfdocking,posteriorprobcombined,c2qscore,iptmbest, andcalibrationtier` appear. The toolbar provides full-text search, CSV export, and filters on BF, posterior probability, BFDR, log₂FC sign, classification, and diagnostic flag. The first column (protein name) is sticky on horizontal scroll.

Evidence tab

Distribution of individual Bayes factors (enrichment, correlation, detection) and the combined Bayes factor across all proteins. Useful for sanity-checking the magnitude of evidence each model is contributing before they are combined.

Calibration tab

Visible when run_simulation = true. Displays:

  • 5 × 5 sensitivity / specificity / precision / recall grids across the (pi_H1, effect_scale) sweep
  • ROC curves and reliability diagrams from the simulation ground truth
  • Platt scaling parameters (a, b) and the Expected Calibration Error (ECE) before and after recalibration; the ECE safety guard skips Platt scaling whenever it would degrade calibration

See Simulation & Calibration for the simulation engine and Platt-scaling methodology.

Sensitivity tab

Visible when prior sensitivity analysis is enabled. Includes the tornado chart of per-parameter posterior swings, the MAD heatmap and Spearman rank-correlation heatmap of pairwise prior settings, the constant-strength simplex grid ternary plot, the decision-boundary stability band (whisker ranges across all proteins), posterior overlay violins for the top-N most sensitive proteins, and the classification stability traffic-light summary (robust / sensitive / fragile). See Prior Sensitivity for methodology.

Mixture Model tab

Visible when evidence combination uses :latent_class or :bma. Contents:

  • 3 × 3 marginal grid — pairwise scatter and density plots for the three Bayes factor dimensions (enrichment, correlation, detection). Points are coloured by EM component assignment (H0 / Agnostic / H1).
  • Marginal density overlays — fitted mixture component densities (Student-t H0, anchored Agnostic at μ = 0, sigmoid-gated H1 with BIC-selected enrichment family) overlaid on the empirical Bayes-factor distributions per dimension.
  • EM convergence — log-likelihood traces across the multi-restart run (default 20 restarts), highlighting the BIC-selected best run.
  • Quality gates panel — KS marginal goodness-of-fit, KL contamination across components, and component separation checks. Each gate is shown with :ok / :warning / :fail colour coding (the standalone "Quality Control" tab was removed in v1.1.4 and folded into this section).
  • Within-class correlation grid — SVG scatter plots of pairwise BF correlations within each EM component (added in v1.1.4).

See Model Evaluation for the BMA section that explains how bf_em and bf_copula are stacked.

Structural Evidence tab

Visible when docking results are available. Shows:

  • ipTM vs MS posterior scatter — relationship between AlphaFold structural confidence and MS-derived posterior probability
  • Before/after update plot — posterior_prob_ms vs posterior_prob_combined per docked pair, illustrating the two-stage Bayesian update
  • Score distribution plots — C2Qscore histogram (or pDockQ for legacy data), docking BF distribution, ipTM distribution
  • Docking results table — sortable list of pairs with ipTM, C2Qscore, calibration tier, BF_dock, quality gate status, and a CSV export
  • Mol* 3D viewer — lazy-loaded from CDN on demand for inspecting predicted structures (.cif files when available)

See Docking Integration for the scoring tiers, quality gates, and the user-mediated three-phase workflow.

Data Quality tab

Visible when run_input_qc = true. Renders the QC summary as a traffic-light card (one row per check) plus per-check Plotly visualisations:

  • Scale detection — flags whether intensities are linear or log-scaled
  • Replicate correlation heatmap — Spearman correlation across replicates with AP-MS-specific thresholds
  • Missingness asymmetry bars — per-condition missingness rates
  • Intensity distribution shape — kurtosis and spike detection
  • PCA separation — Fisher-ratio-scored sample/control separation, with cascading complete-case fallback (100 % → 80 % → 50 % → skip)

See Data Quality Control for definitions and thresholds.

Differential tab

Appears only in differential reports (generate_differential_report). The differential template ships a simpler tab strip — Results and Evidence — and a dashboard with n_gained, n_lost, n_unchanged, condition-specific counts, and the thresholds used (posterior_threshold, bfdr_threshold, delta_log2fc_threshold, dbf_threshold). The Results tab contains the differential volcano (Δlog₂FC vs log₁₀(dBF), coloured by gain / loss / unchanged classification), the differential results table, and an MA plot. The Evidence tab contains the per-evidence differential BFs, the classification summary bars, and the side-by-side condition comparison.

Methods tab

Always visible. The Methods tab combines the auto-generated publication-ready text, the prior specification table, per-model subsections, the Analysis Parameters table, and the Reproducibility code block.

Auto-generated methods text

The methods paragraph is automatically generated per analysis from the actual CONFIG used — the package version, regression likelihood (Normal vs robust Student-t), evidence combination method, and the protein counts at each BFDR threshold are all interpolated from the run. This text lives only in the report (and the companion methods.md written next to it); there is no static methods.md page in the docs because that would inevitably drift from the per-run configuration.

A representative excerpt from generate_methods_text(config, results):

AP-MS data were analyzed using BayesInteractomics v1.2.1 (Julia v1.12). A total of
5029 proteins were evaluated for interaction with the 'F8A1' bait protein using 3
control experiment(s) and 3 sample experiment(s).

Protein-protein interactions were scored by integrating evidence from three independent
Bayesian models: (1) a Beta-Bernoulli model for detection probability, (2) a HBM for
log2 fold-change enrichment, and (3) a Bayesian robust (Student-t) linear regression
model for dose-response correlation. Bayes factors were combined using BMA (LOO stacking
weights over Copula and 3c-EM sub-models). Significant interactors were defined at BFDR
≤ 0.05; 142 proteins met this threshold (38 at BFDR ≤ 0.01).

Below the overview the report renders the full Prior Specification Table (Kruschke 2021 BARG-style), then per-model subsections (Detection, Enrichment, Correlation, Evidence Combination, and Calibration when applicable). Each subsection has a "Show details" toggle revealing the full parameterisation.

Analysis Parameters and Reproducibility

The Analysis Parameters table enumerates every field of CONFIG (raw field names, e.g. poi, refID, combination_method, jzs_r_scale, run_simulation, run_validation, run_docking) so that another researcher can reproduce the run exactly.

The Reproducibility code block at the bottom of the Methods tab is generated by generate_reproducibility_block(config) and includes the package version, Julia version, generation timestamp, output directory, input files, and the full CONFIG parameter dump in copy-pasteable form.

Differential Analysis Report

diff = differential_analysis(config_A, config_B,
    condition_A = "WT",
    condition_B = "Mutant",
    config = DifferentialConfig(generate_report_html = true)
)

# Manual generation
generate_differential_report(diff)
generate_differential_report(diff; output = "diff_report.html")

Cross-tab Synchronisation and Glossary

The report uses a single shared selection state across all tabs (introduced in v1.1.2). Clicking a protein in the volcano plot, the rank-rank plot, the results table, the evidence scatter, the within-class correlation panels, or the docking table highlights it everywhere — including in the structures viewer if the corresponding .cif is available. This auto-discovery wiring removes the need to manually re-select a protein when switching tabs.

Plot explanations follow a two-layer pattern (v1.1.2): each plot has a "What is this?" toggle showing a biologist-friendly paragraph (explanation-bio) and a more detailed statistical paragraph (explanation-stat). Roughly 45 plots ship with this treatment, and a 19-term glossary (Bayes factor, log₂ fold change, posterior probability, PEP, BFDR, local FDR, enrichment, correlation, detection, prior sensitivity, BMA, …) is wired in via dotted-underline tooltips.

Architecture

The HTML reports are designed to be fully self-contained:

  • Single file output — All CSS and the analysis JSON blob are embedded directly in the HTML; nothing is fetched from disk after the HTML is opened.
  • CDN libraries — Plotly.js (interactive plots), DataTables.js (tables), Bootstrap 5 (layout), and the Mol* viewer (lazy-loaded only on the Structural Evidence tab) are pulled from CDN at first open. An internet connection is needed the first time you open a report; browsers will then cache the libraries.
  • Data embedding — Analysis data is serialised to JSON and injected into the template at the {{REPORT_DATA_JSON}} placeholder. A companion sidecar JSON file (e.g. interactive_report_data.json) is written next to the HTML so that subsequent regenerations can merge new sections (such as docking) without reparsing the entire run.
  • Zero new Julia dependencies for serialisation — JSON serialisation uses the package-internal json_object / json_array / json_string / json_number helpers (src/reports/json_utils.jl); the only external JSON dep is JSON3, which is already used elsewhere.
  • Responsive layout — CSS Grid sized for desktop reading; mobile layouts collapse the within-class correlation grid and the dashboard cards.

API Reference

BayesInteractomics.Reports.generate_report — Function
generate_report(results::DataFrame, config::CONFIG; output=config.output.report_file)

Generate a self-contained interactive HTML report from analysis results.

The report includes:

  • Interactive volcano plot and rank-rank plot (Plotly.js, CDN)
  • Searchable/filterable results table (DataTables.js, CDN)
  • Static PNG embeds for evidence, diagnostic, and sensitivity plots
  • Auto-generated methods section text
  • Reproducibility metadata

The generated HTML file can be opened in any modern browser without any additional software installation.

Arguments

  • results::DataFrame: Final results DataFrame from run_analysis().
  • config::CONFIG: Analysis configuration (used for parameters and file paths).

Keywords

  • output::String: Path for the generated HTML file. Defaults to config.output.report_file.

Example

results, ar = run_analysis(config)
generate_report(results, config)
source
BayesInteractomics.generate_differential_report — Function
generate_differential_report(diff::DifferentialResult; output)

Generate a self-contained interactive HTML report for a differential interaction analysis.

The report includes:

  • Dashboard summary (N gained / lost / unchanged / condition-specific)
  • Interactive Plotly differential volcano plot (Δlog₂FC vs log₁₀(dBF), coloured by classification)
  • Searchable/filterable DataTables results table
  • Static PNG / SVG embeds for all existing differential plots
  • Analysis metadata

Arguments

  • diff::DifferentialResult: Output from differential_analysis().

Keywords

  • output::String: Path for the HTML file. Defaults to replacing the results file extension with _report.html.
source

Exported entry points:

  • generate_report(results::DataFrame, config::CONFIG; output = config.output.report_file) — main standard report builder.
  • generate_differential_report(diff::DifferentialResult; output) — differential report builder.

Output paths are managed through OutputFiles:

output = OutputFiles("/path/to/results")
output.report_file          # default: <basedir>/interactive_report.html
output.report_methods_file  # default: <basedir>/methods.md

config.generate_report_html::Bool (default true) controls automatic invocation of generate_report at the end of run_analysis.
